# Exemple — Incident de production ServiceNow → anomalie JIRA

> Illustration du circuit **production → recette** : un incident remonté par le support client dans **ServiceNow (SNOW)** est qualifié par le testeur, reproduit en QUALIF, transformé en anomalie **JIRA** pour l'équipe de développement, puis le correctif est vérifié avant clôture de l'incident.
> (Incident fictif, sur la version précédente v1.3.2.)

## 1. Ticket SNOW reçu
| Champ | Valeur |
|---|---|
| Numéro | INC0012874 |
| Ouvert par | Support client N1 |
| Catégorie | Application mobile / Billets |
| Impact / Urgence | 2 — Moyen / 2 — Moyen → Priorité P3 |
| Description client | « Mon billet a disparu de l'appli quand j'ai changé la taille du texte de mon téléphone. Contrôlé dans le bus, j'ai dû payer une amende. » |
| Appareil déclaré | Samsung Galaxy A54, Android 14 |
| Groupe d'affectation | Équipe produit TransiGo — QA |

## 2. Qualification par le testeur (J+0)
1. Lecture des logs applicatifs fournis par le N2 : aucune erreur serveur → piste **affichage côté app**.
2. Reproduction sur Galaxy A54 de la matrice ([05](../05-matrice-appareils.md)) : police système à 200 % → la liste des billets s'affiche mais **le QR code sort de l'écran** et n'est pas défilable.
3. Non reproduit sur iPhone (Dynamic Type) ni sur Pixel 7 à 200 % → **spécifique One UI** (zoom d'affichage + police cumulés).
4. Mise à jour SNOW : *« Reproduit en QUALIF, spécifique Samsung police 200 % + zoom écran. Contournement communiqué au N1 : réduire la taille de police. Anomalie JIRA TGO-482 créée. »*

## 3. Anomalie JIRA créée — TGO-482
- **Titre** : [Android/Samsung] Avec police 200 % + zoom écran, le QR code du billet est hors écran et non défilable
- **Sévérité** : Majeur (contournement existe) · **Lien** : INC0012874 (SNOW)
- Étapes, attendu / obtenu, capture, appareil + version OS + version app, fréquence 100 %.

## 4. Suivi et clôture
| Étape | Responsable | Statut |
|---|---|---|
| Correctif (mise en page défilable, QR prioritaire) | Dev mobile | Livré v1.3.3 |
| Vérification sur Galaxy A54 + non-régression ciblée « billets » sur la matrice P1/P2 | Testeur | ✅ OK |
| Ajout d'un cas de test permanent **CT-M08** (police agrandie) au cahier de recette | Testeur | ✅ Fait |
| Résolution SNOW + information du N1 pour réponse client | Testeur → Support | ✅ Clôturé |

**Leçon retenue (rétrospective)** : la matrice d'appareils inclut désormais systématiquement un Samsung, et les paramètres d'accessibilité système (taille de police) font partie de la non-régression manuelle avant MEP.
